## 一、「返回＝受理」语义落地

- **调用点契约显式化**（`app.py` `_autosave_current_workspace` docstring）：True＝受理——后台路径仅代表已入队（worker 异步落盘，atexit flush 兜底），调用方不得据 True 断言已落盘；同步路径（dict 会话态/回滚开关）True＝已落盘；真实落盘以 `session_state['_workspace_last_saved'] / '_autosave_last_error'` 为准。
- **调用点事实核查**：app.py:1067/1371 两处 `force=True` 调用均**不消费返回值**、失败统一走状态键——受理语义在调用侧天然成立，本单把契约写成文字供后续调用方遵循，零行为变更。
- **测试锁定**：`test_accepted_return_true_before_persist`——用旗标法（orig_save 调用记录）证明「返回 True 时 worker 尚未走到 save_workspace，flush 后恰好落盘一次」。注：首版用 `load_workspace() is None` 探针是错的（create_project 后本就返回 schema 存根，首跑通过属时序侥幸），已修正。

## 二、换案阈值实测入码（替代 5MB 假设）

实测脚本 `tmp/measure_snapshot_threshold_h91206.py`（DataFrame.to_csv + base64，与 `workspace.build_workspace_snapshot` 序列化配方一致，.venv python 单线程）：

| df 规模 | CSV 体量 | b64 体量 | 序列化+编码耗时 | tracemalloc 峰值 |
|---|---|---|---|---|
| 1000×50 | 0.37MB | 0.49MB | 94.6ms | 3.5MB |
| 3000×200 | 5.20MB | 6.93MB | 1118.7ms | 27.0MB |
| 6000×400 | 21.84MB | 29.12MB | 4252.6ms | 113.8MB |
| 12000×400 | 44.87MB | 59.83MB | 8410.4ms | 233.5MB |

结论：耗时 ≈190ms/MB 线性；驻留内存峰值 ≈5.2×CSV 体量。**旧 5MB 假设偏紧**（5.2MB 已需 1.1s）。新阈值＝**序列化 CSV 10MB**（≈worker 单次 ~2s、内存峰值 ~52MB）：`autosave_bg.SNAPSHOT_WORKER_CSV_MB_THRESHOLD = 10.0`（b64 换算常量随附），注释写明基准条件与复现命令。

**消费点**：worker 落盘前检查 `len(ws['df_b64'])`，超阈值打 WARNING（含实测体量与方案 A 建议），`_result` 增加 `df_b64_mb` 观测字段；未超不告警。
